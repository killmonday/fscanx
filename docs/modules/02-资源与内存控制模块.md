# 模块：资源与内存控制

## 模块定位

覆盖扫描器运行时的内存占用控制：HTTP 响应体读取策略、缓冲区池化、协程池 sizing。不包含功能逻辑本身（指纹识别、POC 判断逻辑在其他模块）。

## 设计决策

- 扫描器目标海量异构，HTTP 一律短连接，不做 keep-alive 复用（与微服务场景相反）。
- 池化 buffer 返回给调用方前必须拷贝，池对象即取即还——池化 buffer 的底层内存不得逸出到池外。
- 所有网络响应读取必须有长度上限；gzip 等解压路径上限独立计算（解压膨胀不可信）。
- 协程池用"按需扩容 + 空闲回收"模式，常驻协程数不为并发峰值买单。
- POC 响应超限为静默截断（与 ParseResponse 丢弃错误现状一致）；指纹读取上限变更视为检测语义变化，需同步本模块文档。

## 运行时内存建议（不改代码的兜底手段）

- `GOGC=20`：更频繁 GC，内存换吞吐（可选）。
- `GOMEMLIMIT=512MiB`：Go 1.19+ 软上限，容器场景适用。
- 排查内存构成：临时加 `import _ "net/http/pprof"` 后 `go tool pprof http://127.0.0.1:6060/debug/pprof/heap`。
